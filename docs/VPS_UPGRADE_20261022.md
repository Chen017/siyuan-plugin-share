# VPS 升级流程与验收

PHP 8.3 安全升级已合并 `main`，并于 2026-10-22（新加坡时间）完成 VPS 备份、构建、安装和自动验收。生产数据库、附件、配置和详细数据快照保留在 VPS；详细验收单在用户本地交付，不写入公共仓库或新的 GitHub Actions 日志。

## 当前日常部署

用户完成站点验收后，已按要求删除本次升级前的数据备份压缩包，并恢复日常自动部署：推送 `main` 后通过 SSH 更新代码、构建镜像、更新 VPS 容器并检查运行版本与健康。手动运行无需选择操作。当前 Action 不执行数据备份或删除备份包；完整回归继续在隔离环境执行。

## 首次安全升级的部署顺序（历史）

1. `main` 推送只运行回归测试，不直接部署。
2. 手动运行 `Deploy Siyuan Plugin Share`：`inspect` 为只读状态检查，`deploy` 为备份后安装。
3. `deploy` 只允许最新的 `main`，且其对应的完整回归必须通过，包括 38 项运行时检查、15 组功能测试以及隔离数据的备份恢复演练。
4. 暂停服务写入，备份实际挂载的数据库、附件和配置；解压到独立目录，逐文件校验 SHA256，检查 SQLite 完整性与外键，生成 `VERIFIED` 标记。详细文件列表、校验值和数据快照只存于 VPS 的私有备份目录。
5. 验证备份后恢复旧服务，再构建新版镜像；切换前获取新数据快照，安装后核对数据指纹、PHP 版本、核心页面、权限拦截及容器健康。
6. 保留旧镜像及回退配置。安装验证失败时尝试恢复旧应用镜像，不自动覆盖数据库。

## 验证范围

完整应用回归在隔离环境执行；生产验收不创建测试账号、分享或附件。真实账号登录和浏览器交互由用户在原有分享站点审核。

备份位于 VPS 本机、网站目录之外，用于安装回退；没有把笔记、附件或配置上传到 GitHub Actions 工件或其他存储。此次升级的数据压缩包已在用户验收后按要求删除；小型验收记录和回退镜像保留。

## 回退

先核对当前状态，再从项目目录使用相应备份目录中的 `rollback.override.yml` 启动保留的旧镜像，同时保留当前生产数据。本次旧数据压缩包已删除，不能再用它恢复历史数据。以后若需使用其他独立备份恢复，应先备份当前数据并在独立目录验证归档，避免覆盖后续新写入。
