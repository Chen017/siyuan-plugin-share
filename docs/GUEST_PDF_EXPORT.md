# 访客 PDF 与逐篇批量下载

打开文档后，点击标题右侧、与「源码」并列的「导出 PDF」，在当前页面弹窗中选择单篇、此文档及子文档、整个分享范围或勾选多篇。未打开文档时不显示按钮。弹窗提供背景模糊与淡入缩放动画，并尊重系统减少动态效果设置。

点击「确定导出」后自动生成并按顺序触发下载，无须新页面、预览或第二次保存。**每篇一个独立 PDF，不合并、不打包 ZIP**。弹窗显示生成进度，失败时可重试剩余篇目；关闭弹窗取消本次任务，取消操作仅作用于当前弹窗的任务。文件名来自文档标题，重名自动加序号。浏览器若询问是否允许连续下载多个文件，需要允许；下载目录和是否逐个询问保存位置由浏览器自己的设置决定。

弹窗显示当前 Cookie 的统计时长、允许篇数、已用与剩余篇数，以及下一次恢复的本地时间和篇数。数据由服务端计算，在确定导出前、完成或失败后刷新，并每 30 秒更新。滚动额度逐篇恢复，不是整点清零；验证码不补充额度。

## 排版与生成

PHP 只整理经过授权和资源检查的文档，PDF 由访客浏览器生成。服务器不启动 Chromium、不存储访客 PDF，也不把文档发送到外部 PDF 服务。打开导出弹窗时预加载约 946 KB 的本地 PDF 组件、文字层组件及来源字体，不创建任务、不扣额度，也不请求验证码。

确定导出后先建立文档清单，再逐篇获取内容、等待排版并生成。单篇使用一路；实际选中多篇时，同一个任务内最多三路并发，每路使用独立排版容器。每篇仍逐页渲染，避免超大画布；文件按文档顺序分别下载。最多保留三篇待下载结果，完成后释放对应容器和画布。失败重试跳过已经下载的篇目。

浅色、深色和移动端均固定白底、深色正文及适合打印的代码配色。沿用 Markdown、KaTeX、图片、表格、代码和图表渲染。导出的 PDF 同时保留页面图像及与正文坐标对齐的 Unicode 文字层，支持选择、复制和搜索正文，并保留下述隐藏元数据。

网页和导出排版均保护 KaTeX 各类专用字体，并为显示公式留出上下空间，减少浏览器字体替换插件造成的截断；正文仍可使用自定义字体。保护不会统一替换数学斜体、黑板粗体或大型括号字体，也不修改公式内部定位与 SVG 裁切。更高优先级的用户样式或插件内联样式仍可能覆盖网站规则，遇到这种情况需在插件中排除本站或公式区域。

正文文字层来自浏览器已排版的文档，不做 OCR；图片中的文字不会自动变得可选。公式复制为渲染后的字符，复杂分式、上下标的纯文本顺序可能与 LaTeX 源码不同。文字层使用带 ToUnicode 映射的透明字形，不下载整套正文字体，也不改变图片排版。使用 PDFium 独立测试中文、希腊字母、emoji、多字形映射、搜索及选区坐标。

导出的 PDF 会在文件的隐藏元数据（XMP）及每页不可见文字层中记录三项来源信息：该篇原文网址、作者「塵」、版权说明「随意传播，禁止售卖」。不加入独立导出编号，不改变可见页面。不可见文字使用嵌入的开源中文字体，便于 PDF 文字提取工具读取。标记可被移除或在重新打印时丢失，不能保证阻止转售。

生成前会等待字体、图片及异步图表完成。远程图片可能受网络和跨域限制；过宽公式、不可拆分的表格或嵌入网页仍需检查下载文件。未加载资源会显示提示。

## 第一层：每个访客 Cookie 独立的滚动额度

默认 **每个访客 Cookie 在滚动 60 分钟内最多开始导出 120 篇**。后台可把篇数设置为 1 至 256，统计时长为 1 至 1440 分钟。这不是全站共享额度，也不另加“每分钟 2 篇”的限制；120/小时只是平均为 2/分钟。

- Cookie 值仅含随机访客 ID 和服务器签名，HttpOnly、SameSite=Lax；有效期由服务器记录，当前为 7 天。
- 时间窗口、已使用篇数、验证码通过状态都记录在服务器 SQLite。Cookie 中没有可自行修改的额度。
- 同一 Cookie 更换 IP、标签页或网站会话不会重置额度。
- 不同 Cookie 不共用个人额度；校园网、公司网络共用公网 IP 不会一起消耗 120 篇。
- 每篇开始生成前向服务器领取一次资格。批量的每篇分别计数；同一个任务对同一篇重试不重复扣数。
- 超额返回“导出太频繁，请稍后再试”，并提示预计恢复时间。减少批量篇数可使用尚未耗尽的余额。
- 预览本身不消耗个人篇数；已领取资格后取消保存或本地生成失败，服务器无法证明实际落盘，不自动退回该篇额度。
- 验证码只验证使用资格，从不清空、补充或重置已用额度。

匿名 Cookie 只近似识别浏览器访客，不能可靠识别自然人。签名防止随意编造有效 ID，但不能阻止删除 Cookie 后申请新 ID。

## 第二层：完全相同指纹、不同 Cookie 时只验证一次

观察窗口沿用后台统计时长，比较指纹哈希的**完全相等**，不做相似匹配。

- 新 Cookie 首次正常使用：直接使用。
- 新 Cookie 的指纹与近期其他 Cookie 完全相同：要求一次图片验证码，不直接封禁。
- 服务器验证正确后，该 Cookie 获得自己的正常额度；在该 Cookie 有效期内不反复验证。
- 原来已经正常使用的 Cookie 不会因为后来有人指纹相同而被反向封禁。
- 指纹相同不证明同一人。机房内真正不同的使用者至多增加一次验证，不共用个人额度。
- 验证码独立于网站注册验证码开关；答案仅以服务器 HMAC 保存，绑定 Cookie、会话及精确指纹，5 分钟过期且成功后销毁，防止重放。错误尝试或反复换图有短暂等待，避免无限猜测。
- 真人仍能反复清 Cookie、验证并取得新身份；该方案提高绕过成本，不能保证严格的“每个自然人 120 篇”。

## 第三层：服务端任务互斥及既有资源保护

**同一个访客 Cookie 最多一个有效导出任务**，跨窗口、跨标签页、不同 PHP 会话都由 SQLite 写事务保证，不依赖按钮禁用或前端变量。服务端同时限制任务内活跃文档：单篇最多一篇，多篇最多三篇；增加批量并发不会允许第二个独立任务。

已有保护继续保留：全站最多 4 个有效任务、每批 120 篇、源内容 2 MiB、排版 8 MiB、关联附件 50 MiB、200 张图片、PHP 整理 15 秒及至多 128 MiB（已有更低限制继续生效）。源内容和附件先检查整批，逐篇准备时继续检查变更；排版、图片及整理时间按整个任务累计，超过上限终止任务。后续篇目失败时，先前已经下载的文件仍保留。这些是资源保护，不是把所有访客的个人额度合并。

任务凭据默认 180 秒；按服务端返回的时间续期，默认约每 60 秒一次，单任务总寿命至多 30 分钟。验证与额度查询合并，每篇的准备与额度领取合并，下载前的权限检查与完成文档合并，不再每生成一页就续期。关闭弹窗、页面或任务完成时主动释放，异常关闭后由超时回收。尚在服务端准备的任务也会记录取消状态。过期、取消或被释放的旧任务在下载前再次验证，停止继续下载。

## 权限与后台

所有数据严格限定当前 share_id。准备、领取每篇资格和保存前复核密码、有效期、访客上限及删除状态；附件继续走受保护的 /s/{slug}/res/ 路由。凭据绑定当前 Cookie、网站会话及分享。响应 private, no-store，不生成公开临时文件。已经读到或下载到本地的内容无法远程撤回。

后台「站点设置 → 访客 PDF 导出」常用界面仅显示开关、统计时长和每位访客允许导出篇数；资源项收起在高级设置。保存直接生效。普通升级保留现有管理员值，config.php 仅作为首次初始化默认值。

维护者如明确要将已运行站点设为 60 分钟 120 篇，可手动运行 Deploy 工作流并勾选 apply_pdf_limits；这是一次显式运维动作，只更新这两个设置，不重置已使用额度、验证状态或其他管理员配置。普通自动部署和不勾选的手动部署不会覆盖已保存的设置。

## 测试

python tests/run.py --php /path/to/php 运行隔离后端回归，--browser 增加真实浏览器的独立文件下载、白底排版、任务互斥和验证码 UI 检查。--docker 使用已构建镜像执行实际 Nginx、PHP-FPM、并发、迁移及持久化检查。所有测试使用临时账号、数据库和附件，不修改生产文档。

PDF 组件固定为 html2pdf.js 0.14.0，版本、哈希及许可见 php-site/assets/vendor/PDF_DEPENDENCIES.md。项目 push main 会触发构建部署；功能分支可先手动运行两套回归，全部通过再合并。
